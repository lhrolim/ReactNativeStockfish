# 🏗️ New Architecture Implementation Guide

## Overview

This document explains how ReactNativeStockfish supports New Architecture (TurboModules).

## Architecture

### Old Architecture (Legacy)
- **Module**: `ReactNativeStockfishModule.kt` (extends `ReactContextBaseJavaModule`)
- **Access**: Via `NativeModules.ReactNativeStockfish`
- **Works**: Always, regardless of New Architecture setting

### New Architecture (TurboModule)
- **Spec**: `src/NativeReactNativeStockfishSpec.ts` (TypeScript interface)
- **Base Class**: Generated by codegen → `android/generated/.../NativeReactNativeStockfishSpec.java`
- **Implementation**: `ReactNativeStockfishModuleImpl.kt` (extends generated base class)
- **Access**: Via `TurboModuleRegistry.get('RNReactNativeStockfishSpec')`
- **Works**: Only when `newArchEnabled=true` and codegen has run

## How Codegen Works

1. **App Build Process**:
   - React Native detects `codegenConfig` in `package.json`
   - Runs codegen to generate base class
   - Base class is created in: `android/app/build/generated/source/codegen/java/com/loloof64/reactnativestockfish/NativeReactNativeStockfishSpec.java`

2. **Library Compilation**:
   - `ReactNativeStockfishModuleImpl.kt` extends the generated base class
   - Compiles successfully because base class exists (from step 1)

3. **Linking**:
   - React Native's autolinking automatically links the codegen library
   - No manual CMake linking needed

## Files Structure

```
ReactNativeStockfish/
├── src/
│   ├── NativeReactNativeStockfishSpec.ts    # TypeScript spec (input for codegen)
│   └── NativeReactNativeStockfish.ts         # JS wrapper (auto-detects TurboModule/legacy)
├── android/
│   ├── src/main/java/.../
│   │   ├── ReactNativeStockfishModule.kt           # Legacy implementation
│   │   ├── ReactNativeStockfishModuleImpl.kt       # TurboModule implementation
│   │   └── ReactNativeStockfishPackage.kt          # Package (isTurboModule: true)
│   └── build.gradle                               # Build config
└── package.json
    └── codegenConfig                              # Codegen configuration
```

## Key Points

1. **Codegen runs at app build time**, not library build time
2. **Base class is generated in app's build directory**, not library's
3. **React Native's autolinking handles everything automatically**
4. **Library's CMakeLists.txt should NOT manually link codegen** (React Native does it)
5. **JavaScript automatically falls back to legacy** if TurboModule not available

## Testing

### Enable New Architecture in App

```bash
# In chesswizard/mobile/
# app.config.js
newArchEnabled: true

# android/gradle.properties
newArchEnabled=true
```

### Build and Verify

```bash
cd android
./gradlew clean
cd ..
npm run dev:android:incremental
```

### Check Codegen Output

```bash
# Should exist after build:
ls android/app/build/generated/source/codegen/java/com/loloof64/reactnativestockfish/NativeReactNativeStockfishSpec.java
```

## Troubleshooting

### Error: "Unresolved reference: NativeReactNativeStockfishSpec"
- **Cause**: Codegen hasn't run yet
- **Fix**: Ensure `newArchEnabled=true` and rebuild. Codegen runs automatically.

### Error: "Cannot specify link libraries for target react_codegen_RNReactNativeStockfishSpec"
- **Cause**: Library's CMakeLists.txt trying to manually link codegen
- **Fix**: Remove manual linking from CMakeLists.txt (already done)

### Module not working
- Check `isTurboModule: true` in `ReactNativeStockfishPackage.kt`
- Verify codegen output exists
- Check JavaScript logs for TurboModule vs legacy detection
